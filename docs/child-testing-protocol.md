# Phase 4 child-testing protocol (gate #8, BUILD-PHASE-4 §10)

**Status: READY TO RUN — requires David to recruit and conduct. Findings file
goes in `/docs/child-testing-findings.md` before the Phase 4 gate closes.**

## Participants

- ≥8 children aged 8–11, recruited via the parent network.
- Written parental consent + child assent (child may stop at any time, no reason needed).
- Ezra pilots the protocol first for protocol-debugging only; his data is excluded from findings.
- Thank-you voucher per family.

## Session rules

- ≤20 minutes per session; parent present throughout.
- **No recordings of faces** — screen capture + written audio notes only.
- Device: the family's own tablet where possible (landscape); note the model.
- Staging environment with the tester family profile; no real accounts.

## Protocol

1. **Unmoderated start (5 min):** hand over at the Crew HQ screen. Observe, don't
   rescue. Note: can they start the loop unaided? Where do they hesitate first?
2. **Task prompts (10 min):**
   - "Can you find a new word for your collection?"
   - "Try a case. If one gets tricky, what would you do?" (Mode shelf comprehension)
   - Deliberately induce a miss if none occurred: do they read the Not-yet beat?
     What do they say about it?
3. **Chat (3 min):** What would you call your detective friend? Which bit would
   you show a friend? Anything that felt confusing or babyish?

## Triage buckets

- **fix-in-phase-4:** comprehension blockers (child cannot proceed or misreads a beat) — fixed and retested before the gate.
- **phase-5:** polish, art, delight gaps.
- **backlog:** everything else, recorded with the child's words where possible.

## Data handling (DPIA §9)

Notes are pseudonymous (Child A–H + age). No names, schools, or contact details
in the findings file. Consent forms stored separately offline by David.
Screen recordings deleted after triage, within 30 days.
